# Data Dictionary — Master Data

Source: `rcd_data/generators/master_data.py` (`MasterDataGenerator`). These
7 tables are the FK backbone every other domain samples from via
`MasterCache` — see `rcd_data/generators/base.py`. PII/retention/legal-basis
detail lives in [[ropa]] and [[data-classification-retention]]; this doc is
schema-only.

## `customers`

| Column | Type | Description |
|---|---|---|
| `id` | uuid | Primary key |
| `name` | string | Person name (B2C/VIP) or company name (B2B) |
| `email` | string | **PII** |
| `phone` | string | **PII** |
| `cpf_or_cnpj` | string | **PII** — valid-check-digit CPF (individual) or CNPJ (B2B), synthetic values only |
| `segment` | enum | `B2C` \| `B2B` \| `VIP` |
| `country` | enum | `BR` \| `MX` \| `PT` \| `US` |
| `state`, `city` | string | Locale-generated |
| `signup_date` | date | Between 2015-01-01 and profile start |
| `ltv_tier` | string | Derived from a Pareto-distributed LTV score |
| `preferred_channel` | enum | `web` \| `mobile_app` \| `in_store` \| `marketplace` \| `phone` |
| `loyalty_points` | integer | 0–50,000 |

## `products`

| Column | Type | Description |
|---|---|---|
| `sku` | string | Primary key, format `{brand3}-####` |
| `name`, `category`, `subcategory`, `brand` | string | — |
| `cost`, `price` | decimal | `price` is list price; `cost` ≈ 40–65% of price |
| `currency` | string | Always `BRL` at the source (all product pricing is BRL-denominated) |
| `margin` | decimal | `(price - cost) / price` |
| `supplier_id` | uuid FK → `suppliers.id` | |
| `weight_kg` | decimal | |
| `launch_date` | date | |
| `is_active` | boolean | First 9 rows (RCD-brand hero SKUs) always `True`; third-party SKUs ~5% inactive |

## `employees`

| Column | Type | Description |
|---|---|---|
| `id` | uuid | Primary key |
| `name` | string | **PII** |
| `email` | string | **PII** |
| `department` | enum | One of 13 values in `config.yaml` `company.departments` |
| `role` | string | `"{department} Specialist"` (IC level) or `"{department} Manager"` (M level) |
| `manager_id` | uuid FK → `employees.id`, nullable | First 5 employees have no manager |
| `hire_date` | date | Between 2008-01-01 and profile start |
| `salary` | decimal | **Restricted** — see [[data-classification-retention]]; drawn from a level-specific normal distribution |
| `location` | string | City, sampled from `stores.city` |
| `employment_type` | enum | `full_time` \| `part_time` \| `contractor` |
| `level` | enum | `IC1`–`IC7` or `M1`–`M5` |
| `country` | enum | `BR` \| `MX` \| `PT` \| `US` |

## `suppliers`

| Column | Type | Description |
|---|---|---|
| `id` | uuid | Primary key |
| `name` | string | Company name — not personal data |
| `country` | enum | `BR` \| `MX` \| `PT` \| `US` |
| `rating` | decimal | 1.0–5.0 |
| `lead_time_days` | integer | 3–60 |
| `payment_terms` | enum | `net_30` \| `net_60` \| `net_90` \| `prepaid` |
| `category` | enum | electronics, appliances, packaging, logistics, components, raw_materials |

## `stores`

| Column | Type | Description |
|---|---|---|
| `id` | uuid | Primary key |
| `name` | string | 5 named flagships (Paulista, Ipanema, Reforma, Chiado, Brickell) + generated |
| `region`, `country`, `city` | string | |
| `type` | enum | `flagship` \| `standard` \| `outlet` \| `pop_up` \| `online` \| `warehouse` |
| `opening_date` | date | |
| `size_sqm` | integer | |
| `manager_employee_id` | uuid FK → `employees.id`, nullable | Always `None` in the generator today — no store→manager assignment logic exists yet |

## `warehouses`

| Column | Type | Description |
|---|---|---|
| `id` | uuid | Primary key |
| `name` | string | `"RCD WH {city} {seq}"` |
| `location`, `country` | string | Cycles through São Paulo/Manaus/Monterrey/Lisbon/Miami |
| `capacity_m3` | integer | 1,000–50,000 |
| `manager_id` | uuid FK → `employees.id`, nullable | Always `None` today — same gap as `stores.manager_employee_id` |
| `type` | enum | `central` \| `regional` \| `dark_store` |

## `fx_rates`

Generated by `utils/fx.py::generate_fx_rates`; not read in detail here — a
daily FX rate table keyed by currency pair and date, feeding `MasterCache.fx_rates`.
No personal data.

---

**Known gaps** (worth fixing if this generator's realism matters for a
downstream demo): `stores.manager_employee_id` and `warehouses.manager_id`
are never populated — every row is `None`. If you need a manager-attribution
story for these tables, that's a generator change, not a docs gap.
